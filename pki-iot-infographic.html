// 01 — Environment

Resource Constraints

RAM / Flash
Limited headroom — full OpenSSL stack often too large. Budget carefully for TLS buffers.
Hardware RNG
Absent on older silicon. Use Linux /dev/urandom + entropy seeding from hardware events. Audit entropy at boot.
CPU Speed
RSA-2048 keygen is costly — 2–8s on low-MHz Cortex-M. Avoid RSA-4096, DH, classic DSA.
Persistent Storage
Some devices lack secure flash. Key material may need re-provisioning on each boot.
No FPU
ECC over prime fields (P-256) handles well in integer arithmetic — no float needed.
// 02 — TLS / Crypto Libraries

Library Selection

Mbed TLS
ARM-native, purpose-built for embedded. Modular — compile only what you need. FIPS-certifiable builds. Backed by Arm Ltd.
WolfSSL
~16–20KB flash, FIPS 140-2 cert available. Strong IoT track record. PKCS#11 and TPM integrations. Commercial support available.
BoringSSL
Hardened OpenSSL fork — use when you have headroom and need a hardened, maintained base.
LibreSSL
Cleaner codebase than OpenSSL, reasonable footprint. Good for standard Linux targets.
OpenSSL
Avoid on constrained hardware. Use only on full Linux systems with ample resources.
// 03 — Cryptography

Algorithm Choices

ECDSA P-256
Primary recommendation. ~10× faster than RSA on ARM with no FPU. Small certs.
Ed25519
Very fast on ARM Cortex-A/M, compact keys. Use if your TLS library supports it (check version).
AES-128-GCM
HW acceleration often present even on older ARM SoCs. Prefer over ChaCha on Cortex-A.
RSA-2048
Acceptable for issuing CAs (offline ops). Never generate on-device. Pre-provision only.
Avoid
RSA-4096 Classic DH Classic DSA MD5 / SHA-1 3DES
// 04 — Certificate Enrollment

Enrollment Protocols

EST (RFC 7030)
Top pick for Linux IoT. HTTPS-based, lightweight client, works behind NAT. Supports re-enrollment and key refresh natively.
SCEP
Older but widely supported across device vendors. Good for legacy fleet compatibility. Simpler client implementation.
ACME
Overkill for most IoT — requires reliable DNS and internet. Useful only for internet-facing gateways.
Pre-provisioning
Best for truly constrained devices. Inject identity cert + key at manufacture or flash time. No on-device enrollment needed.
Zero-Touch
Combine EST + device attestation (IDevID → LDevID) for automated fleet onboarding per IEEE 802.1AR.
// 05 — Key Material

Key Storage

ARM TrustZone
Gold standard if SoC supports it. Isolate key ops in secure world via OP-TEE (open-source TEE). Keys never leave secure world.
TPM / SE
Hardware secure element provides tamper-resistant key storage. Use PKCS#11 to interface with it from Linux userspace.
Encrypted FS
If no HW root of trust: encrypt key store with a KEK derived from device-unique secret (burned fuses, serial). dm-crypt / eCryptfs.
tmpfs + re-provision
Store keys in RAM only; re-provision from CA on each boot via EST. No key persisted on flash at all.
PKCS#11
Standardize key access regardless of underlying backend (SW token, TPM, HSM). Enables CA infra interop.
Never
Plaintext keys on flash Hardcoded keys in firmware World-readable key files
// 06 — CA Infrastructure

Lightweight CA Options

step-ca
Smallstep · Modern · REST/ACME/EST
Best-fit for IoT fleet management. Easy deployment, strong automation, good docs. Supports ACME, EST, SCEP, JWK.
EJBCA
Enterprise · Heavy · Full-featured
Full PKI platform. Use for large device populations needing RA workflows, audit trails, HSM integration.
cfssl
Cloudflare · Simple · Scriptable
Clean Go CLI and API. Ideal for automated cert pipelines, CI/CD signing, and internal service mesh PKI.
Dogtag / FreeIPA
Strong choice for Red Hat / Linux-heavy environments. Integrated LDAP, Kerberos, and CA management.
CA Hierarchy
Offline Root → Online Issuing CA is minimum viable for any production IoT deployment.
// 07 — Threat Model

Attack Surface & Defensive Posture

Rogue CA / Cert
Attacker installs rogue root or intercepts enrollment. Mitigate: certificate transparency, pinning on constrained devices, strict trust anchor management.
Key Extraction
Physical access to device enables flash dump or JTAG key extraction. Mitigate: TrustZone, secure boot, fuse-locked keys, no plaintext key on flash.
MITM via Downgrade
Force TLS 1.0/1.1 or weak cipher suites. Mitigate: enforce TLS 1.2+ minimum, disable weak ciphers in Mbed/WolfSSL config at compile time.
Cert Expiry / No Revocation
Offline devices miss CRL/OCSP updates. Certs expire silently. Mitigate: short-lived certs + automated EST re-enrollment, stapled OCSP, Delta CRLs.
Entropy Starvation
Low-entropy boot causes weak key generation. Mitigate: seed /dev/urandom from hardware events, use ATECC608 or similar entropy source, delay keygen until entropy pools are full.
Firmware Signing Bypass
Modified firmware bypasses cert-based auth. Mitigate: secure boot (U-Boot verified boot, ARM Trusted Firmware), sign firmware images with code-signing PKI.
Rogue Device Enrollment
Cloned device ID enrolls fraudulently. Mitigate: IDevID (factory-installed identity) + attestation, RA policies requiring hardware attestation before cert issuance.
Side-Channel Attacks
Timing / power analysis on crypto ops. Mitigate: use constant-time ECC implementations (Mbed TLS has options), avoid homegrown crypto, physical shielding if required.
// 08 — Compliance & Standards

Gov / Federal Standards

NIST SP 800-57
Key management lifecycle guidance. Authoritative reference for key generation, storage, distribution, and destruction policies.
FIPS 140-2 / 3
WolfSSL and Mbed TLS both offer FIPS-validated builds. Required for federal-adjacent deployments handling sensitive data.
FPKI
Federal PKI cross-certification. Device certs that need to chain to federal trust anchors must follow FPKI policies.
DoD PKI
CAC/PIV for operators; device identity certs from DoD-issued CAs. Devices may need to validate DoD intermediate CAs.
IEEE 802.1AR
IDevID / LDevID standard for device identity. Foundation for zero-touch provisioning and supply chain integrity.
// 09 — Future Readiness

Post-Quantum Readiness

NIST PQC
ML-KEM (Kyber), ML-DSA (Dilithium), SLH-DSA (SPHINCS+) finalized. Plan migration path now for long-lived device fleets.
ARM Impact
PQ algorithms are compute-heavy. ML-DSA on Cortex-M4 is feasible; SLH-DSA is very slow. Evaluate per device class.
Hybrid Mode
Run classical ECDSA + ML-DSA in hybrid during transition. Both must fail for compromise. Supported in OQS-BoringSSL fork.
OQS Project
Open Quantum Safe provides liboqs + integrations for OpenSSL, BoringSSL, WolfSSL. Start evaluation now on test hardware.
Timeline
Devices deployed today with 10+ year lifespans should have a PQ migration path in their firmware update architecture.
// 10 — Monitoring & Ops

PKI Operations

Cert Transparency
Log all issued certs to a CT log. Enables detection of rogue issuance. Critical for internet-facing device gateways.
Revocation
OCSP stapling preferred for constrained clients. Delta CRLs for offline-capable devices. Pre-fetch and cache on device.
Short-Lived Certs
24–72hr cert lifetime eliminates revocation complexity. Requires reliable EST re-enrollment. Best practice for zero-trust IoT.
Audit Logging
Log all CA issuance events, enrollment requests, and key operations to tamper-evident store (syslog-ng, Loki, or HSM audit log).
mTLS
Mutual TLS for all device-to-service communication. Both sides present certificates. Zero-trust network foundation.
